# UMI 박스 적재 데이터의 IGRIS-C WALK_LOW 재생 환경 — 설계

작성 2026-11-23, PRO6000(`super`). 사용자 요청과 2026-11-23 대화에서 확정한 내용이다.
구현 위치는 `igris/umi_walklow_replay/`이며 기존 소스·출력은 수정하지 않는다.

## 목적

`rcvsungmincho/Box_palletizing_UMI_macos_intern_merged`(사람이 UMI로 녹화한 박스 적재)를
IGRIS-C가 시뮬레이션에서 그대로 따라 하게 한다. 실기에서 쓰는 구조와 같아야 한다:
하체는 제조사 WALK_LOW가 서 있게 두고, 허리 3축과 양팔 14축(합 17축)만 SDK LowCmd로 움직이며,
재생 중에 IK를 푼다.

## 사용자가 정한 것

- 물리는 **제조사 MuJoCo 3.2.7 + 제조사 컨트롤러(WALK_LOW) + SDK LowCmd**, Isaac Sim은 장면 제작과 렌더.
  (2026-11-23 "벤더 물리 + Isaac 렌더" 선택. 전부 PhysX로 하는 안은 제조사 WALK_LOW를 못 돌려서 제외.)
- UMI 데이터의 원점은 로봇 pelvis다.
- 벽과 책상은 기존 UR5e 책상 장면(`real2sim/ur5e_desk`)을 쓴다.
- 롤테이너·바닥·검은 박스·파지 대상 박스를 실제처럼 넣는다. 로봇 배치는 재생이 잘 되도록 맡긴다.
- IK는 4090 구현을 참고해 고치거나 새로 만든다.
- RCV hand 실기 값(도): 왼 MCP 325.8984 / CMC 321.7676 / IP 248.2031,
  오른 MCP 170.0684 / CMC 111.3574 / IP 170.9473. 약간 굽힌 좌우 대칭 자세가 목표이고,
  조립 영점 때문에 어긋나면 대칭에 맞게 고친다.

## 조사로 확인한 사실

- 데이터: 34 에피소드, 15 Hz, 70~103초. `observation.state == action` =
  좌/우 `xyz + qx,qy,qz,qw`(pelvis 기준) + `head.yaw`. 관절값은 없다.
- 손 프레임 축은 로봇 EE 규약과 같다: 왼손 손바닥 법선 −y, 오른손 +y, 손가락 방향 −z, x는 엄지 쪽.
  오른손은 왼손보다 약 30° 더 흩어져 있다(녹화 보정 차이로 추정).
- 손 원점은 로봇 EE 원점(MCP 축)이 아니라 **손바닥 접촉면**에 가깝다. 근거: 박스를 든 구간의
  양손 간격이 0.276 ± 0.018 m로 박스 길이 0.27 m와 같다.
- 한 에피소드 = 박스 3개. 집는 높이(양손 중점 z) 0.30 / 0.10 / −0.025 m, 놓는 높이 0.02 / 0.10 / 0.295 m.
  강체 파지를 가정하면 박스 높이 0.14~0.16 m → **우체국 2호 27×18×15 cm**.
  검은 케이스 윗면과 롤테이너 적재면은 둘 다 pelvis 원점 아래 **0.10 m**(34 에피소드에서 2 cm 이내 일치).
- 집는 곳(수평): 양손 중점 (0.43, −0.30) m, head yaw −0.6 rad. 놓는 곳: (0.15, 0.41) m, head yaw +1.4 rad.
  세 박스를 한 기둥으로 쌓는다.
- 4090 `igris/umi_isaac_replay`(9월): 골반 고정 PhysX, 허리는 head yaw로 외부 지정, 팔만 HL-IK.
  위치 5 mm·자세 2° 동시 충족 0%, 파지 0/3. 손 프레임 축을 추정으로 맞췄던 것이 주원인.
- 이 PC에 `igris-sim:jazzy` 이미지, `igris/ws/install`, `env_isaaclab`(Isaac 6.0.1), 빈 GPU가 있다.
  `igris/isaac_vendor_room`의 `prepare → start → bringup → worker` 구조가 요청한 구조와 같다.

## 접근

1. **기존 `isaac_vendor_room` 실행기 재사용 + 새 장면·새 재생 워커 (채택).** 제조사 모델·컨트롤러·
   격리 컨테이너·관측기·Isaac 렌더러가 검증돼 있다. 새로 만드는 것은 장면, 재타깃, IK, 재생 워커뿐이다.
2. 4090 `umi_isaac_replay` 이식. PhysX 골반 고정이라 WALK_LOW 요구와 맞지 않는다.
3. `isaac_vendor_room/run.py command`에 옵션 추가. 그 함수는 HTD 이송 실험 분기가 얽혀 있어
   기존 실험을 깨뜨릴 위험이 크다. 새 워커를 따로 둔다.

## 구성

```text
dataset(15 Hz, pelvis 기준 손바닥 포즈)
  → retarget: 손바닥 접촉점 → 로봇 EE 원점 (손별 상수 변환)
  → 100 Hz 보간 목표
  → IK(허리 3 + 팔 14, pelvis 루트)  ← LowState 측정각으로 시작
  → SDK LowCmd (PJS, 100 Hz, 상체 17축 + 목 2축 유지, 하체 gain 0)
  → 제조사 bridge_sim → controller(WALK_LOW) → MuJoCo 3.2.7 (로봇 + 장면)
  → 관측기 body pose → Isaac Sim 렌더 (RGB)
```

| 파일 | 역할 |
|---|---|
| `episode.py` | 에피소드 추출, 집기/놓기 구간 검출, 장면 치수 추정값 계산 |
| `retarget.py` | 손바닥 접촉점 → 로봇 EE 원점 변환, 압착량 |
| `kinematics.py`, `ik.py` | 제조사 MJCF에서 읽은 pelvis→EE 기구학, 17축 IK |
| `scene.py` | 장면 USD 생성(방·바닥·롤테이너·케이스·박스·로봇 참조) |
| `hands.py` | RCV hand 자세(실기 값 ↔ 시뮬 관절각), 좌우 대칭 검사 |
| `prepare.py` | 장면을 제조사 MJCF에 합성(기존 `isaac_vendor_room.prepare` 호출 + 손 자세·접촉 설정) |
| `worker.py` | 컨테이너 안 재생 루프(LowState 구독, IK, LowCmd 발행, 기록) |
| `run.py` | `prepare / start / bringup / replay / render / stop` 진입점 |
| `analyze.py` | 추종 오차, 박스 상승·이송·적재 판정 |
| `test_*.py` | 기구학·IK·재타깃·장면 치수 오프라인 검사 |

## 장면 (pelvis 기준 설계 좌표, 로봇은 +X를 본다)

- 로봇: 원점, yaw 0. WALK_LOW 기립 높이는 실행 때 측정해 물체 높이를 맞춘다.
- 검은 케이스: 윗면 z = pelvis − 0.10 m, 박스 기둥 중심이 (0.43, −0.30)에 오도록 배치.
  검은 패널 + 알루미늄 모서리. 치수는 영상 기준 추정(약 1.2×0.6 m 상판).
- 대상 박스 3개: 27×18×15 cm, 케이스 위 한 기둥. 긴 축 방향은 집는 순간의 양손 방향에서 계산.
  질량 0.3 kg(빈 박스 가정), 마찰 0.6(기존 실험의 실리콘–종이 근사).
- 롤테이너: 3면 강관 프레임 + 뒤판, 안쪽에 갈색 박스 더미. 앞쪽 적재면 윗면 z = pelvis − 0.10 m,
  놓는 기둥 중심 (0.15, 0.41). 뒤쪽 줄은 더 높게.
- 방: UR5e 책상 장면의 벽·책상·바닥. 배경이며 로봇과 충돌하지 않는 거리.
- 물리 부하를 줄이려고 동적 물체는 박스 3 + 케이스 1 + 롤테이너(적재면 포함) 1로 제한한다.
  기립이 끝난 뒤 실제 pelvis 위치·방향에 맞춰 한 번 배치한다(기존 staging 기능).

## 재타깃

데이터 포즈 `T_d`(손바닥 접촉점)에서 로봇 EE 목표 `T_ee = T_d · Trans(−c + s)`.
`c`는 EE 프레임에서 본 로봇 손바닥 접촉 중심(기존 값 좌 `[0, −0.0308, 0.068]`, 우 `[0, +0.0308, 0.068]`,
손 모델에서 다시 확인), `s`는 법선 방향 압착량(기본 한쪽 8 mm). 회전은 그대로 쓴다.
모든 값은 `retarget.json`에 기록하며 실행 옵션으로 바꿀 수 있다.

## IK

- 변수: 허리 yaw/roll/pitch + 좌·우 팔 7축 = 17. 루트는 pelvis(데이터 원점과 동일).
- 매 제어 주기에 가중 감쇠 최소자승 미분 IK를 반복: 양손 위치·자세 오차 최소화,
  기준 자세 쪽 정규화, 관절 한계(제조사 URDF, 여유 2°)와 속도 한계 준수.
- 허리 yaw는 head yaw를 약한 참고값으로만 쓴다(사람이 몸을 돌린 방향). 허리 roll/pitch는 IK가 정한다.
- 수치 계산은 numpy만 쓴다. 컨테이너 안에서 LowState와 같은 프로세스로 돌려 통신 지연을 없앤다.
- 실패(잔차 초과)는 기록하고 최선의 해를 보낸다. 관절 급변은 속도 한계가 막는다.

## 제어 계약

- 토픽·형식은 기존과 같다: `igris_c_001/rt/lowcmd`(SDK LowCmd, PJS), `rt/lowstate`, `rt/robotstate`.
- 상체 gain은 기존 재생 프로파일(`replay_gains.toml`)을 쓴다. 하체는 q/dq/tau/kp/kd 모두 0.
- 진행: 기립 유지 발행기에서 인계 → 준비 자세(에피소드 첫 자세)로 quintic 이동 → 장면 배치 →
  재생 → 마지막 자세 유지.
- 중단 조건: WALK_LOW 이탈, LowState 0.25 s 이상 끊김, pelvis z < 0.7 m.
- 격리 컨테이너(`--network none`, private IPC) 안에서만 실행한다. 실기와 연결되지 않는다.

## RCV hand

손 모델은 URDF의 `dof_joint_mcp`, `dof_joint_cmc`, `dof_joint_mcp_thumb`(실기 이름 MCP/CMC/IP)를 쓴다.
실기 엔코더 영점이 코드에 없으므로: 시뮬 자세는 좌우 대칭인 "약간 굽힘"으로 정하고,
주신 실기 값은 그 자세에 대응하는 실기 목표로 `hand_pose.json`에 함께 기록한다
(실기 값 − 시뮬 각 = 영점 오프셋). 자세는 렌더로 확인한다. 손은 재생 중 자세 고정이다.

## 성공 기준

1. 오프라인: 기구학이 제조사 MuJoCo FK와 일치(위치 0.1 mm 이내), IK가 에피소드 전체에서
   관절·속도 한계를 지키고 잔차를 보고.
2. 시뮬: WALK_LOW 기립 유지, LowCmd 100 Hz 전 구간 발행, 관절 추종 오차 보고.
3. 과제: 박스별 상승·이송·적재 여부를 접촉 없는 구간과 최종 위치로 판정. 영상 생성과 과제 성공은 따로 보고.

## 하지 않는 것

- 실기 동작, 실기 DDS 연결.
- 보행(cmd_vel) 명령. 하체는 제자리 기립만.
- 제조사 로봇 모델(질량·관절·구동기·solver) 변경. 손 자세와 손–물체 접촉 활성화만 추가한다.
- 손의 능동 제어(파지 중 MCP 구동). 고정 자세로 양팔이 눌러 잡는다.

## 구현자가 정할 것

케이스·롤테이너의 세부 치수와 재질, 텍스처 제작 방법, IK 가중치, 압착량, 카메라 구도.

## 구현하면서 바뀐 것 (2026-11-23 시뮬 결과 반영)

처음 설계대로는 박스를 한 번도 옮기지 못했다. 시뮬에서 드러난 원인과 대응은 다음과 같다.
근거 실행은 모두 `outputs/umi_walklow_replay_20261123_*`에 있다.

| 드러난 문제 | 근거 | 대응 |
|---|---|---|
| 양 손바닥이 박스 면에 7~13° 기울어 닿아 박스가 손 사이에서 돎 | 34개 에피소드에서 손바닥 법선이 박스 축과 왼손 12.3°, 오른손 34.3° 일정하게 어긋남(흩어짐 약 5°) | 손별 상수 회전 보정 + 든 구간은 양손을 한 쌍(평행·대향·박스 길이 간격)으로 명령. 집을 때와 놓을 때는 쌍을 수평으로 맞춤 |
| 메시 충돌은 손–박스 쌍마다 접촉점이 하나라 회전을 못 막음 | 박스가 들린 뒤 90° 이상 회전 | 손바닥·손끝을 덮는 평판 접촉면 하나 + 비틀림 마찰(condim 4, 반경 30 mm). 손 메시는 제조사 원본처럼 비충돌 |
| 사람이 박스마다 다른 높이를 잡음(바닥에서 10.7 / 4.2 / 7.4 cm) | 낮게 잡은 둘째 박스에서 접촉면이 아래 박스까지 물어 함께 들림 | 박스 높이와 기록만으로 계산한 수직 보정으로 매번 박스 중간 높이를 잡음 |
| 놓을 때 손이 덜 벌어짐 | 첫 박스가 손에 낀 채 다시 딸려 옴 | 누르는 양(22 mm)은 든 구간에만, 그 밖에는 기록보다 한쪽 30 mm 더 벌림 |
| 팔을 뻗거나 숙이면 보행 제어기가 골반을 8~16 cm 옮김 | 가장 낮은 박스에서 허리 숙임이 0.64 rad까지 커지고 손이 못 닿음 | 로봇을 7 cm 앞·3 cm 오른쪽에 세우고 작업면을 0.847 m로 올림. IK는 허리 roll/pitch를 마지막 수단으로만 쓰고 범위를 roll ±0.15, pitch −0.15~+0.08 rad로 제한 |
| 발이 바닥에서 미끄러지고(분당 간격 20 cm, 방향 10°) 골반이 발 위에서 최대 10 cm·6° 흔들림 | 세 번째 박스가 9 cm 넘게 어긋나 놓이면 넘어짐 | 목표를 방 기준으로 고정: 측정한 골반 자세(시뮬 실측)로 보정. 허리 숙임 제한이 없으면 이 보정이 악순환을 일으킴 |
| 촉각이 늦게 켜지는 가벼운 파지 | 에피소드 10·20에서 집는 순간이 공중으로 잡힘 | 촉각 이력 임계값(켜짐 8, 꺼짐 3.5) + 양손 간격이 일정한 구간으로 확장 |

"UMI 데이터의 원점은 로봇 pelvis"라는 계약은 재생 시작 시점의 pelvis에 대해 지킨다. 그 뒤에는 데이터 기준 좌표계를
방에 고정된 것으로 두고(녹화 때도 그랬다) 골반 이동을 보정한다. `--anchor none`이 보정 없는 순수 pelvis 기준 재생이다.

성공 기준 3번의 판정은 **기록의 마지막 자세**로 한다. 놓은 직후에는 멀쩡하다가 손을 빼면서 넘어뜨린 경우가 있었다.

## HL-IK 팔꿈치 prior (2026-11-23 추가, 선택 기능)

요청: 재생 영상의 팔 자세가 어색하니 HL-IK를 적용해 사람 시연처럼 보이게 할 수 있는지. 사용자가 적용을 지시했다.

접근:

1. **FiSTA 팔꿈치 예측을 IK의 보조 과제로 (채택).** `igris/hl_ik`의 학습된 네트워크를 그대로 쓴다. 손 포즈는 건드리지 않는다.
2. HL-IK의 가중 최소자승(손이 팔꿈치에 양보)을 그대로 이식. 박스를 손바닥 사이에 누르는 재생에서는 손 오차를 허용할 수 없다.
3. 손 궤적 자체를 로봇 체격으로 재타깃. 효과는 가장 크겠지만 "데이터 재생"의 범위를 바꾸므로 사용자 결정 사항으로 남겼다.

구현:

- `elbow_prior.py`: 체크포인트를 npz로 내보내고(torch는 호스트에만 있다) numpy로 평가. 포즈는 torso 좌표계에서 어깨 원점 기준
  xyz + wxyz, 이력은 30 Hz 5개, 목표는 한 주기(33 ms) 앞의 손 목표. 이력에는 예측값이 아니라 실제 명령 자세를 넣는다.
- `ik.py`: 팔마다 손 Jacobian의 영공간(스위블)에서만 팔꿈치를 목표로 옮긴다. 한 틱에 관절 여유의 절반까지만 쓴다.
  관절 한계 0.10 rad 안쪽과 박스 표면 8 cm 안쪽에서는 prior 대신 벗어나는 방향으로 돈다.
- `worker.py`: 박스 자세(시뮬 실측)를 pelvis 좌표계로 바꿔 IK에 넘긴다. 준비 자세는 학습 평균 팔꿈치 위치에서 시작한다.
- `prepare.py`/`run.py`: `--elbow-prior`, `--checkpoint`. `analyze.py`: `arm_posture` 지표.

결과와 한계는 `README.md`의 "HL-IK 팔꿈치 prior" 절에 있다. 요약: 팔꿈치는 바깥으로 벌어지지만(스위블 평균 오른팔 7~11° → 28~48°)
영상에서의 차이는 작고, 에피소드 0의 적재 성공이 17/18에서 5/9로 떨어져 기본값은 꺼 두었다.

## 텔레옵 관절 데이터로 본 원인 (2026-11-23 추가)

목적(사용자): UMI 데이터로 학습한 VLA가 내는 EE 포즈(허리 + 양손)를 이 로봇에서 문제없이 실행할 수 있는가.

`kimyg119/Igris_Teleop_Box_Palletizing`(로봇 관절 기록)을 기준으로 삼았다. `teleop.py`가 기록 관절을 그대로 보내는 재생과,
같은 동작의 손 포즈를 IK로 푸는 재생을 만든다. 워커에는 `--joints`, `--no-scene` 두 옵션만 더했다.

- 실행 경로(IK → LowCmd → WALK_LOW)는 로봇이 낼 수 있는 손 포즈에 대해 문제가 없다(README 표 1).
- UMI 손 목표는 텔레옵과 속도, 어깨–손 거리, 어깨 roll 한계 접촉에서 다르다(README 표 2). "손이 어깨보다 높아서"라는
  앞선 설명은 틀렸다: 텔레옵에서도 78%의 시간 동안 손이 어깨보다 높다.
- cuRobo(`igris_curobo`)는 같은 목표에서 손 오차가 더 크고 GPU가 필요하다. 고유한 장점은 자기충돌 검사와 chunk 궤적
  생성(`ActionChunkIK`)이다(README 표 3).

남은 결정: UMI 손 목표를 로봇 분포(속도·거리·방향)로 옮기는 재타깃을 어디서 할지 — 학습 데이터 단계인지 실행 단계인지.

## UMI 재타깃 시험 (2026-11-23 추가, 선택 옵션)

사용자 선택에 따른 시험이며 기본 동작은 바꾸지 않았다. 후보를 시뮬 없는 IK로 먼저 가르고 시뮬로 확인했다.

- `--rebase-waist`(워커): 허리 yaw 기준을 손 목표와 같이 골반 회전만큼 돌린다. 원래의 누락을 메우는 것이다.
- `--toe-in DEG`(준비 단계): 손을 손바닥 접촉점 둘레로 돌려 손끝을 모은다. 접촉 평판은 되돌려 박스와의 접촉은 그대로 둔다.
- `IK(pin_waist_yaw=True)`: 허리 yaw를 기준대로 직접 명령하고 나머지 16축으로 손을 푼다. 사용자가 제안한
  "허리 따로, 팔은 몸통에서" 방식을 같은 IK로 시험하기 위한 것이며 워커에는 연결하지 않았다(오프라인 결과가 나빴다).

결과는 README의 "UMI 재타깃 시험" 절. 에피소드 0에서는 뚜렷이 나아졌지만(한계 접촉 27~33% → 9~18%, 4/4 성공)
다른 에피소드에서는 왼 손목 yaw가 새로 한계에 붙는 경우가 있어 고정 각 toe-in은 기본값이 아니다.

가변 toe-in(2026-11-23, 사용자 선택에 따른 추가 시험): `IK(toe_range=…, toe_pivot=…)`가 손끝 모음 각을 범위 안에서 고른다
(손 과제를 "손바닥 점 위치 3 + 회전 2"로 줄이고, 남는 회전은 관절 한계 회피에 쓴다). 준비 단계 옵션은 `--toe-free`,
접촉면 옵션은 `--pad capsule`. 오프라인 자세 지표는 가장 좋았지만 시뮬 적재는 고정 12°보다 못해(1/4~2/3 대 4/4)
기본값이 아니다. 원인은 접촉 모델이다: 평판은 각이 변하면 들뜨고 캡슐은 잡는 힘이 약하다.

## 실행기 보강: mink IK와 자기충돌 제약 (2026-11-23 추가, 선택 옵션)

사용자 지적("처음부터 구현하면 구멍이 있을 것, mink라도 쓰자")에 따라 새 제약 처리는 직접 구현하지 않고 mink에 맡겼다.

- `mink_ik.MinkIK`: 제조사 MJCF에서 기구학만 남긴 17축 모델(geom 없음, 다리 고정)에 FrameTask 2개 + PostureTask,
  제약은 ConfigurationLimit, VelocityLimit, 제조사 결합 한계(`CoupledLimit`), 자기충돌(`SelfCollisionLimit`).
- `collision.SelfCollision`: cuRobo 로봇 설명의 충돌 구를 그대로 쓰는 간격 계산. mink의 기하 쌍 방식은 구 3,666개에는
  느려서, 간격과 최근접 구는 numpy로 구하고 그 기울기(MuJoCo 점 Jacobian)만 QP 제약으로 넘긴다.
- 컨테이너에는 mink가 없어 패키지 폴더를 읽기 전용으로 붙인다(`run.MINK_PY`).
- 기본 IK는 바꾸지 않았다. 결과는 README의 "mink IK와 자기충돌 제약" 절.

아직 하지 않은 것(이 절을 쓴 시점): 잡는 동안 양손 쌍 제약 해제. 속도 제한과 mink 기본화는 아래 절에서 했다.

## 기본 설정 변경 (2026-11-23 저녁, 사용자 지시)

1. mink IK를 기본으로 (`--ik numpy`로 되돌림).
2. 박스를 놓은 뒤의 뒤틀림: 접촉 기록으로 충돌임을 확인(왼 전완–롤테이너 옆 패널 184 N, 오른 정강이–케이스 136 N).
   `scene.CART_SETBACK`, `CASE_SETBACK`으로 받침을 옮겼다. 박스 위치는 기록 그대로다.
3. 접근할 때 팔꿈치 벌어짐: 텔레옵 관절 기록의 경향에 맞춤. 빈손 구간의 손 방향 가중을 낮추고
   (`retarget.orientation_weight`), 팔 자세 기준을 텔레옵 기록의 최근접 평균으로 (`posture_prior.TeleopPosture`).

근거와 수치는 README의 "현재 기본 설정" 절. 남은 문제는 보행 모드에서 발이 벌어지고 로봇 위치가 움직이는 것으로,
발–받침 접촉과 세 번째 박스 실패의 원인이다. 받침을 더 옮겨서는 해결되지 않았다.

## 관절 속도 제한과 장면 치수 수정 (2026-11-23 밤, 사용자 지시)

1. 속도 제한("속도 제한 진행"): `governor.py`의 진행 조절기. 관절을 따로 자르지 않고 기록 경로 위의 진행을 늦춰서
   관절 속도 1.0 rad/s, 빨라질 때의 가속도 6 rad/s²를 지킨다. 워커가 기본으로 쓰고(`--joint-speed 0`으로 끔),
   로그의 `path`가 기록 시간이며 분석은 이 값으로 든 구간을 찾는다. 느려지는 쪽의 가속도는 묶지 못했다
   (앞으로 올 목표를 미리 봐야 한다). 골반 이동 보정도 같은 한계에 묶인다.
2. 장면 치수(사용자 실측: 롤테이너 폭 92 cm, 쌓인 박스 높이 80 cm): 폭은 맞았고 작업면이 0.847 m로 4.7 cm 높았다.
   `scene.SURFACE_TOP = 0.80`으로 고치고 갈색 박스 높이를 그에 맞췄다(20.9 cm).
3. 롤테이너 오프셋을 (10, 4) cm에서 (6, 6) cm로: 옆으로 10 cm 옮긴 탓에 세 번째 박스가 오른쪽 패널을 스쳤다.
   `--cart-setback`으로 바꿀 수 있다. 폭 92 cm 안에서는 어느 오프셋도 팔과 박스 모두에 여유를 주지 못한다.

수치와 시뮬 결과는 README의 "장면 치수 확인과 재시험", "관절 속도·가속도 제한" 절.
아직 하지 않은 것: IK에 롤테이너 패널을 장애물로 넣기(빈손 구간의 전완–패널 접촉), 감속 쪽 가속도 제한(미리 보기),
보행 모드에서의 위치 이동. (서는 위치 (0.03, −0.03)은 뒤에 시뮬로 확인했고 0/3이었다.)

## 케이스 높이, 기록 손 프레임 보정, 서는 위치 (2026-11-23 밤, 사용자 지시)

1. 케이스 높이(사용자 실측 77 cm): 장면은 0.80 m였다. `scene.CASE_TOP = 0.77`로 분리했다. 롤테이너 적재면(0.80 m)과의
   차이 중 기록에 없는 몫은 집는 쪽 손 목표에만 더한다(`prepare.height_profile`, 워커와 `offline.solve`가 적용).
2. 잡기 직전 왼손의 방향 전환: 기록(트래킹) 문제였다. 두 손 프레임이 일정하게 어긋나 있다(손바닥 축 둘레 28°,
   원점 6 cm). `hand_calibration.py`가 든 박스에서 상수를 재고, `prepare`가 에피소드에 적용한다(`--raw-hands`로 끔).
   오른손이 기준이다(어느 손이 맞는지는 데이터로 알 수 없다 — 사용자가 본 자연스러운 쪽).
   보정된 에피소드에는 예전의 손바닥 법선 보정(`MEASURED_BOX_AXIS`)을 쓰지 않는다.
3. 양손의 자세를 위치보다 먼저 맞춘다(`retarget` `grasp_turn_in_s` 1.5초).

근거와 수치는 README의 "기록 손 프레임 보정" 절.
4. 서는 위치: 네 자리를 시뮬로 비교했고 (0.07, −0.03)을 그대로 둔다(4/6; 뒤로 0/3, 앞으로 1/3, 집는 쪽으로 1/3).
   실패는 "손이 모자람 → 허리 숙임 → 보행 제어기가 골반을 뒤로 뺌 → 더 모자람"의 되먹임이다. README "서는 위치 재확인" 절.

## 숙임 → 골반 후퇴 되먹임 차단 (2026-11-24, 사용자 승인 "차단 진행")

검토한 방법 셋 가운데 사용자가 고른 것은 "우리 코드가 쥔 고리를 끊는다"이다.
- (채택) 방 고정 보정이 상체가 포화된 동안의 골반 후퇴를 따라가지 않게 하고, 속도 제한기에 최소 진행 속도를 둔다.
  작고, 시뮬 6회 단위로 비교할 수 있다. 대가는 손이 물러난 만큼 못 미치는 것.
- 숙임 자체를 무게중심 기준으로 제한: 발단을 줄이지만 낮은 박스에서 손이 항상 더 모자란다. 필요하면 추가.
- 다리를 쓴다(한 걸음 다가서기, 골반 낮추기): 근본 해결이지만 제조사 보행 명령의 불감대와 박스를 든 채의 걸음 때문에 큰 작업.

구현: `anchoring.py`(`ReachHold`, `strain`), `governor.RATE_FLOOR`, 워커의 `--no-reach-hold`·`--hold-lean`·`--rate-floor`.
못 미친 몫은 방에 고정된 벡터로 든다(뻗는 방향의 거리로 들면 손이 도는 동안 잘못 쌓인다).
결과와 한계는 README의 "숙임 → 골반 후퇴 되먹임 차단" 절. 같은 날 확인한 서 있을 때의 흔들림은 허리 게인으로 줄지 않았다
(README "서 있을 때의 흔들림과 허리 게인 시험" 절).
아직 하지 않은 것: 정강이–케이스 충돌과 골반 방향 회전(남은 실패 2/12의 원인), 감속 쪽 가속도 제한.
